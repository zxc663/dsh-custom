**单一权威源**：`D:\DeepSeek\dsh-plugin-dev\content\discipline.md`（v5 全文）。本节只列 v5 相对 v4 的三处增量，不复制全文（防双份漂移）：

### 1.1 状态行（中文枚举）

```
Context: state=<新任务|续接|单发> L=<L1|L2-S|L2-F|L3> clarify=<无|待澄清|已澄清> approval=<无需|待批准|已批准|已拒绝|豁免:理由>
```

机器解析映射（**设计要求，未实现**——现有解析器只认 `L=` 代码枚举，src L268-272；中文值落地前先改解析器与测试）：

| 字段 | 中文枚举 | 英文映射（机器值） |
|---|---|---|
| state | 新任务 / 续接 / 单次 | new / resume / single |
| clarify | 无 / 待澄清 / 已澄清 | none / pending / resolved |
| approval | 无需 / 待批准 / 已批准 / 已拒绝 / 豁免:理由 | not_required / pending / granted / denied / waived |
| L | L1 / L2-S / L2-F / L3 | 不变（代码枚举，现有解析器已认） |

### 1.2 承载协议（新增 §2，全文）

> - 承载根：项目工作区**根目录新建专用文件夹**（建议 `.xinuo/`，名称以项目规则文件为准），工作流要求的承载文档都写在这里；模板从按需层 templates/ 复制，禁空占位。
> - 一档制单文件四区（防双写漂移），四者职责分开：**一面状态**（≤10 行，STATE 单行结构化，挂会话锚，多会话每会话一行锚）｜**教训库**（症状→根因→解决→预防＋证据＋命中计数；同坑修订原条目）｜**偏好段**｜**流水区**（固定格式，**时间戳精确到分**，>200 行或 >150KB 轮转）。
> - 脚本复用：轮转/检索/对账脚本从插件或技能目录复用，不复制进工作区承载——工作区只放数据。
> - 会话末必做：流水一行＋状态段刷新；不更新=交接断链。
> - 边界：单发/纯只读问答不建承载，声明「单发：未建承载」。

### 1.3 工具触发矩阵新增目标登记工具

> - 目标登记工具（create_goal 类）：**必须**=长程多轮目标型任务（L2-F 及以上/跨多轮无人值守）；**跳过**=L1/简单任务/单轮可完成的任务——不为一两轮的小事开目标工具。

### 1.4 思考要求与质疑审查（v6 新增 §2，全文在 content/discipline.md）

> - **需求四层**：场景条件（背景上下文，可解释输入，**不作约束执行**）｜任务约束（真实硬限制，逐条显式验证）｜需求表现（表质要求，质疑对象）｜本质需求（为什么，方案对准它）。
> - **三质疑**：必要性质疑／完整性质疑／解决性质疑；要求与事实/约束冲突→直说＋纠正建议（事实优先，不静默执行）；需要裁决→走 §1.3 提问协议。
> - **方案三想一合**：首个方案通常非最优——先列 **≥3 候选**（取舍＋返工成本），再在约束下组合最优（组合依据写明）；L2-F 必须，L2-S 仅关键方案，L1 豁免。
> - **调研对比**：方案/选型/版本/最佳实践先调研再答（K1/K4 联动：官方文档/现有方案/可信信号）；训练知识只作候选，不作结论。

### 1.5 收尾与留档（v7 新增）

> - **state 定案**：仅 新任务/续接/单次 三值——**收尾不是 state 值**，是任务收尾回合的固定协议。
> - **收尾五件**（收口工具之外的必要交付，已按必要性调研固定）：①交付摘要（gate summary，防回合文本丢失）②验收对照（逐条核销：通过/未过/未验证）③承载留档（流水＋状态段）④未决点清单（真待办）⑤备份清理（临时备份删、重要备份留）。
> - **备份规则**：备份只写承载文件夹 `backups/`，附 `backup-info.txt`（时间到分/节点/作用/原因）；不越过工作区（红线联动）。
> - **注释纪律**：注释与文档只写决策与依据（为什么），不写「用户说」——出处留承载流水。
> - **目标模式超时**：仅在用户明示「自主推进/无人值守/你决定」类授权时带超时默认策略；无授权=提问必须等人；按默认推进的每次决策留档（Ruling 行）。

## 2. 状态行裁决（中文枚举与去留问题）

### 2.1 state 字段去留（不变）

**保留，但降格为「定位锚」，不承载执行语义。** 运行时不解码 `state`（只解析 `L=`，src L268-272；`Context: state=` 仅作复述计量锚，src L306-308）。历史上 task-open 等级为空是解析器没读的问题——将来运行时消费新字段前必须先改解析器与测试。

### 2.2 方案 B 拆分（不变）

`clarify` 与 `approval` 独立：已澄清 ≠ 已批准；三种状态（意图不明/意图明有风险/意图明无风险）可独立表达。

### 2.3 枚举与映射细则（v5 更新）

1. 四字段全中文封闭枚举（§1.1），禁止行内附注，备注移行外；禁止中英混写（如 `state=new` 与 `state=新任务` 并存）。
2. 中文值落地为模型输出契约；解析器改造（按映射表识别）为设计要求——**先改解析器与测试，再要求模型输出**（历史教训同源）。
3. 追加任务重给判级；判级缺失由运行时强制补（§7 D1，设计要求）。

## 7. 运行时设计要点（均为「设计要求，未实现」）

### D1 判级强制与追加判级
运行时解析 `L=` 状态行；缺失→steer 强制补判级；追加消息后未给新判级→注入「追加判级」提示。收益：判级从自觉变强制，token 只花在缺失时。反例：纯聊天误判=骚扰；解析器读错=假缺失。副作用：沿用 steer 熔断。**v5 联动**：解析器须先支持中文枚举映射（§1.1）再上线强制。

### D2 任务清单强制（L2 复杂任务）
discipline_task 扩展「任务清单＋验收断言」登记；检测「L2-F 无登记」→开工侧注入提示（补 §4.1 缺口）。语义型任务允许声明 exempt 出口。

### D3 工作区边界守卫（三档权限）
只读查看=禁一切写；工作区内操作=禁越区写（路径前缀判定，非正则）；完全权限=不拦截、全量记录。零 token、确定性判据。

### D4 L3 重定位（回应硬移植批评）
三层防线：第一层=边界守卫（D3）；第二层=L3 命令正则（命令形态兜底）；第三层=文本红线（形态绕行显式违规）。完全权限下第一、二层转记录。

### D5 完全权限记录模式
拦截退位但不离场：全部转记录，审计不缺失。

### D6 提问倒计时参数
ask_user_question 增加 countdown：严重停点不设超时；目标模式必带，超时按预设默认继续并如实记录。原则：不能因为阻碍而阻碍，也不能不应阻碍而继续。

### D7 收口证据并入输出
gate 通过后证据行由宿主在输出结尾追加渲染，模型不复述；渲染失败回退工具返回通道。

### D8 压缩信号与技能重载
宿主压缩后注入信号，模型按 compression-reload.md 重载序执行（默认保精度）。

### D9 环境盘点（运行时增强）
开工盘点系统＋工作区工具/技能；提示词层已落地，运行时增强=清单注入（设计要求）。

### D10 渐进加载引擎（检测→注入）
三条检测点共用「检测→注入」：判级缺失（D1）/清单缺失（D2）/压缩信号（D8）；M 强制/S 按症状，路由表见 §3。

### 8.2 承载文件夹设计（先看原有，再给方案）

**原有设计（shisan-xinuo-workflow，templates 实证）**：承载=项目内两件+项目规则文件——`memory/agent-log.md`（一档制四区：状态段≤10 行首行 STATE／教训区 T1+T2／偏好段／流水区，>200 行或 >150KB 轮转 archive）、`docs/project-info.md`（六节索引）、项目级规则文件（AGENTS.md 等）；时间戳=流水 `YYYY-MM-DD HH:mm`（细则 #311「留档时间戳到分钟」）；脚本（rotate/lookup/syncer）在技能安装目录，不进项目。

**本体系承载设计（用户架构：元提示词→工作流固定模板→承载文档；承载=项目工作区根目录新建文件夹）**：
